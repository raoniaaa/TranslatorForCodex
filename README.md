# Translator for Codex

在 Codex 中输入中文，停顿后自动转换成英文。

Translator 是一个轻量的 macOS 桌面伴侣：保留你习惯的中文输入法，通过一个可拖动的小宠物控制翻译。点击开启后，工具等待你完成选词和输入，再调用你配置的 API 整段翻译，将英文填回消息草稿。

> 当前为 **macOS 实验版本**，仅适配 Codex 桌面应用的普通文本输入框。Windows 适配尚未实现。本项目是独立工具，与 OpenAI 无官方关联。

## 功能

- **中文输入，英文草稿**：默认停顿约 2 秒后整段翻译，避免逐词拼接影响语义。
- **点击一次，持续开启**：点击宠物切换模式；切换窗口后返回 Codex 输入框会自动继续。
- **看得见的翻译状态**：宠物显示等待选词、等待停顿、正在翻译、完成和错误等状态。
- **可拖动的桌面宠物**：记住拖动后的位置，输入框高度变化时保持原位。
- **自定义 API**：支持兼容 Chat Completions 的服务，可填写地址、模型名称和 Key。
- **本地保存设置**：地址、模型、停顿时间和 Key 在重启后恢复，无需重复填写。
- **保护正在编辑的内容**：继续输入、移动选区或切换焦点时取消旧结果；选词期间暂停处理。
- **保留代码和链接**：代码块、行内代码和 URL 使用占位保护；模型破坏占位符时保留原稿。

工具只修改草稿，发送消息仍由你操作。翻译质量和响应速度取决于所选模型与 API 服务。

## 快速开始

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | macOS 13 或更新版本 |
| 目标应用 | Codex 桌面应用 |
| 编译工具 | Go 1.24+、Swift、Xcode Command Line Tools |
| 翻译服务 | 兼容 Chat Completions 的 API |
| 已适配输入源 | macOS 系统简体拼音、ABC、US |

Go 核心仅使用标准库；原生界面使用系统 AppKit 和 WebKit，无需 Electron 或 Node.js 运行时。构建脚本生成当前机器架构的应用。

### 从源码构建

获取源码并进入项目目录：

```sh
git clone https://github.com/raoniaaa/TranslatorForCodex.git
cd TranslatorForCodex
```

然后构建应用：

```sh
# 若尚未安装 Xcode Command Line Tools
xcode-select --install

# 构建并启动
./scripts/build-macos.sh
open dist/Translator.app
```

`Translator.app` 位于 `dist/` 目录。关闭设置窗口后，工具仍在菜单栏运行；点击菜单栏的「译」可打开设置或退出。

### 配置翻译服务

1. 在设置中填写 API 地址、模型名称和 API Key，点击「保存设置」。
2. 输入一段中文并点击「试译」，确认服务可用。
3. 按界面提示前往「系统设置 → 隐私与安全性 → 辅助功能」，为 **Translator** 授权。
4. 回到 Codex，点击消息输入框；宠物出现后，点击它开启翻译模式。

API 地址支持以下形式：

```text
https://your-provider.example/v1
https://your-provider.example/v1/chat/completions
http://127.0.0.1:8000/v1
```

远程服务需要 HTTPS，本机服务允许 HTTP。模型名称必须与服务提供的名称一致。无需鉴权的本机服务可以留空 Key。

### 日常使用

1. 正常输入中文并完成选词。
2. 停顿约 2 秒后，宠物显示「正在翻译」。停顿时间可在设置中调整。
3. 完整译文填回草稿后，检查内容并照常发送。

如果请求期间继续输入，旧结果会被丢弃，工具等待下一次停顿。这里的“输入完成”依据停顿判断；思考时停顿较长，也可能触发翻译。

翻译后继续追加中文时，工具会结合之前保留的中文上下文重新整段翻译。选中文本或在段落中间编辑时暂停替换，光标回到末尾后继续。

| 操作 | 效果 |
| --- | --- |
| 点击宠物 | 开启 / 关闭翻译模式 |
| 拖动宠物 | 移动并保存位置 |
| 右键宠物 | 打开设置或重新定位到输入框旁 |
| `Control + Option + E` | 开启 / 关闭翻译模式 |
| `Control + Option + R` | 恢复最近一次替换前的草稿，前提是草稿未再修改 |
| `Command + Z` | 使用目标编辑器的撤销功能 |

翻译开关在本次运行中保持；重新启动应用后，需要再次开启。设置中的「看看翻译宠物」只演示状态，不调用 API，也不修改输入框。

## 数据与本地存储

应用直接请求你配置的翻译服务，待翻译的草稿会发送到该服务；本项目不提供中转服务。Key 用于该服务的请求鉴权，不会出现在设置状态接口中。

macOS 默认保存位置：

```text
~/Library/Application Support/CodexTranslator/
├── settings.json          # API 地址、模型、停顿时间、密钥文件引用
└── credentials/
    └── <id>.key           # API Key
```

- **Key 以明文保存在本地文件，不使用 macOS 钥匙串。** 密钥目录权限为 `0700`，密钥文件和设置文件权限为 `0600`。
- Key 输入框保存后清空，界面以保存状态提示；同一服务留空保存会保留原 Key。
- 切换 API 主机不会自动沿用旧 Key；可在设置中删除已保存的 Key。
- 草稿和译文仅保留在本次进程内存中，应用不写入翻译历史日志。
- 不读取 Codex 登录凭据，不自动发送消息。

本地设置网页仅监听 `127.0.0.1`，使用随机会话路径、Host / Origin 校验和 CSP。模型请求拒绝自动重定向。

## 已知限制

- **目前仅支持 macOS + Codex。** Windows、其他桌面应用和其他输入法尚未适配。
- **输入法状态检测属于实验功能。** 当前通过候选浮窗判断选词状态，并非系统提供的精确组合态 API。候选窗隐藏、输入法行为变化或 Codex 升级可能影响判断。
- **首版针对普通文本草稿。** 附件、提及和复杂富文本组合不在已验证范围内，工具会对检测到的不支持内容暂停处理。
- **整段写入依赖辅助功能接口。** 写入前会重新核对草稿和选区，写入后最多校正一次光标；若编辑器未接受定位，需手动点击文本末尾。
- **尚未签名分发或公证。** 默认构建使用本机 ad-hoc 签名，适合从源码构建测试，不是已完成安装分发的正式版本。

## 常见问题

### 已经授予辅助功能权限，仍提示未授权

给 Codex 授权不等于给 Translator 授权。另外，本机 ad-hoc 签名可能在重新构建后使旧授权失效。

在辅助功能设置中移除旧 Translator，使用应用设置页的「定位当前应用」找到新版本并重新添加，再点击「重新检测权限」。

### 为什么没有自动翻译？

检查翻译模式是否开启、服务是否试译成功，以及辅助功能权限是否生效。当前焦点需要位于 Codex 普通消息输入框，光标在末尾且没有选区。正在选词、不支持的输入源或未闭合的三反引号代码块都会暂停翻译。

API 请求失败后，同一草稿不会无限重试；修改草稿或重新开启模式可重试。

### 为什么更换模型后，译文风格或速度不同？

Translator 使用你配置的模型完成翻译。工具会要求保留语义、否定关系、段落和技术术语，但实际质量与延迟由服务和模型决定。可以先在设置页试译，再开启自动填回。

## 开发

```sh
# Go 测试与静态检查
go test -race ./...
go vet ./...

# 构建 macOS 应用
./scripts/build-macos.sh

# 仅启动设置与试译网页，不连接桌面
go run ./cmd/translator --demo
```

网页模式会在终端打印临时本地地址。可用 `python3 scripts/mock_api.py` 启动固定响应测试服务；将它输出的地址填入试译设置，模型填写 `fixture` 可测试成功响应，填写 `fixture-error` 可测试 HTTP 503。该服务不调用真实模型，不用于评价译文质量。

| 环境变量 | 用途 |
| --- | --- |
| `TRANSLATOR_CONFIG_DIR` | 自定义设置目录，测试时可隔离真实配置 |
| `TRANSLATOR_BASE_URL` | 覆盖本次运行的 API 地址 |
| `TRANSLATOR_MODEL` | 覆盖本次运行的模型名称 |
| `TRANSLATOR_API_KEY` | 从进程环境传入 Key |
| `TRANSLATOR_SIGNING_IDENTITY` | 构建时指定代码签名身份，默认 `-`（ad-hoc） |

Go 测试覆盖停顿、选词阻塞、过期结果丢弃、焦点变化、撤销保护、API 响应处理以及本地配置保存与恢复。原生输入法和光标行为仍需在实际 macOS / Codex 环境中验证。

### 项目结构

```text
cmd/translator/          # 应用入口
internal/engine/         # 翻译状态机与替换保护
internal/provider/       # Chat Completions 请求与代码/链接保护
internal/credentials/    # 本地密钥文件存储
internal/desktop/        # Go 与原生助手通信
internal/web/            # 本地设置服务与 Web UI
native/macos/            # 辅助功能适配、菜单栏、宠物、草稿写入
scripts/                 # 构建脚本与测试服务
docs/images/             # README 截图
```

构建产物 `dist/`、本地配置、密钥文件和日志已列入 `.gitignore`。提交问题时，请附上系统版本、输入法和复现步骤，并隐去 Key 与私人草稿。
